# DeutschLern: Project Architecture & Status Report

## 1. Project Overview
DeutschLern is an enterprise-grade, monorepo-style application for learning German (CEFR Levels A1 - B2). 
It features a meticulously crafted UI for the student-facing frontend and a powerful administration panel for the backend content management system (CMS).

## 2. Core Architectural Constraints
**CRITICAL RULE:** The project strictly enforces a **Two-Folder Architecture**. The root directory (`D:\Germany\Learn German\German Website`) MUST only contain two primary folders:
1. `Frontend`
2. `Backend`

No additional root-level folders (e.g., `packages`, `apps`, `gateway`) are permitted.

## 3. Architecture & Data Flow

### The Frontend (Port 3000)
- **Framework:** Next.js (React 19, Tailwind CSS v4, TypeScript).
- **Gateway Role:** The Frontend natively acts as the single unified Gateway using Next.js `rewrites()`. Any traffic to `http://localhost:3000/backend/*` is seamlessly proxied to the Backend application.
- **Current State:** The Frontend UI is heavily developed with modules for Vocabulary, Grammar, Sentences, Quizzes, and Exams. Currently, data is statically loaded from large `.json` files via ES6 imports in `Frontend/src/levels/*/index.ts`. 

### The Backend (Port 3001)
- **Framework:** Next.js (Admin CMS), Node.js.
- **Database Layer (Prisma):** The Backend owns the `dev.db` SQLite database and the `prisma/schema.prisma` definitions. The database is strictly normalized to the Third Normal Form (3NF).
- **Core Services:** 
  - The Backend contains the N-Tier Architecture services: `IRepository`, `JsonRepository`, `PrismaRepository`, and `ContentService` (located in `Backend/src/services` and `Backend/src/repositories`).
- **API Layer:** The Backend exposes REST API endpoints (e.g., `/api/vocab/[level]`, `/api/grammar/[level]`, `/api/user-auth/*`) which query the SQLite database via `PrismaRepository`.
